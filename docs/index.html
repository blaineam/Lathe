01 — Why

Porting the C tools is the wrong answer

Most media tooling on Apple platforms is a command-line binary wrapped in a process spawn. That is fine on a desktop and impossible on iOS, where fork/exec is not available at all.

The instinct is to port the C tools. But the system frameworks already do most of the work, in hardware, with no licence exposure — ImageIO encodes HEIC, AVIF, JPEG, PNG, GIF and TIFF; AVFoundation probes and extracts frames; VideoToolbox encodes H.264 and HEVC with constant-quality control; Vision does OCR.

Lathe is the thin, well-tested layer over those frameworks — plus the few permissive libraries that fill the gaps they really do leave.

Two gaps are real. WebP has no encoder in ImageIO on any Apple platform, so libwebp is vendored. MP3 likewise, so LAME is. Everything else is the system doing the work it was built for.

02 — Implemented

What it does

PROBE

Media probing

Duration, codecs, dimensions, frame rate, channels — from the container header. A four-hour film costs what a four-second clip costs.

IMAGE

Still encoding

HEIC, AVIF, JPEG, PNG, TIFF, GIF and WebP, with the capability checked before encoding so a format that cannot be written fails clearly.

VIDEO

Transcoding

H.264 and HEVC through VideoToolbox, constant-quality and hardware-accelerated, with chapters and timing preserved across the rewrite.

AUDIO

Loudness & MP3

Mean volume the way the familiar filter reports it, an audibility decision that stops as soon as it knows, and MP3 encoding via LAME.

FRAMES

Frame extraction

Thumbnails at a time and a max edge, every n seconds, or a fixed count sampled evenly — plus raw grayscale frames for hashing that never touch disk.

META

Tags

iTunes-style atoms, ID3, EXIF/IPTC and PDF attributes through one model — written beside the original and swapped in only once it worked.

DOC

Documents

PDF page counts, compression, and searchable-PDF OCR through Vision.

LOOKUP

Metadata lookup

Film and television titles, episode numbering and artwork from TMDb, using the caller's own key.

FETCH

Network ingest

A separate product that is never in the umbrella, so an App Store target cannot link it by accident.

The app it was built for

Sami

Sami is a media optimizer for Apple Photos, folders and cloud drives — one universal app across iPhone, iPad and Mac. It reclaims storage by compressing exactly the photos, videos and PDFs you choose, with a side-by-side preview before anything is committed.

Lathe is its engine. Every capability on this page exists because a shipping app needed it to work on a phone, offline, without spawning anything — which is why the library is shaped the way it is rather than the way a command-line tool would be.

The library is free and always will be. Sami is where the work is paid for.

03 — A detail worth the space

The audibility cliff

Mean volume over a whole file is the standard way to ask “does this have sound?” — and it is quietly wrong. Ten minutes containing two seconds of speech averages about −45 dBFS: indistinguishable, by that number, from a file with nothing in it at all.

That is not a corner case. It is an ordinary phone video with one spoken sentence in it.

// a measurement
let volume  = try await LoudnessProbe().meanVolumeDB(url: url)

// a decision — stops as soon as it has an answer
let audible = try await LoudnessProbe().hasAudibleAudio(url: url)

meanVolumeDB reports the same statistic the familiar command-line filter prints, so existing thresholds keep working. New logic should use hasAudibleAudio, which reads windowed peak and short-term RMS and returns the moment it knows. A loud file is decided in the first window; only a genuinely silent one is read to the end, because that is the only way to be sure.

That distinction is the whole design in miniature: answer the question the caller actually has, and say which one was answered.

04 — Linking

One repo, separate products

Lathe ships several products, chosen individually. That split is not cosmetic — it is how an App Store target stays clear of code it should not contain.

ProductContentsApp Store
LatheThe media-processing modules, togetheralways safe
LatheCoreShared types, progress, errorssafe
LatheImageStill images, capability probesafe
LatheVideoProbing, frames, transcodingsafe
LatheAudioLoudness, audibility, transcodingsafe
LatheMetaTags, across every storesafe
LatheDocPDF and archivessafe
LatheMP3MP3 encoding via LAMEsafe
LatheLookupTMDb, with the caller's own keysafe
LatheFetchNetwork ingestnever in the umbrella

The umbrella product is the media-processing modules and will never absorb the ingest module. Depending on Lathe therefore cannot pull it in by accident; linking it has to be a deliberate line in your own manifest.

05 — Install

Take only what you need

// Package.swift
.package(url: "https://github.com/blaineam/Lathe.git", from: "0.8.4")

// then, per target
.product(name: "LatheVideo", package: "Lathe")

Or take the umbrella — Lathe — which re-exports every media-processing module and deliberately excludes ingest.
