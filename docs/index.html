01 — Why

Porting the C tools is the wrong answer

Most media tooling on Apple platforms is a command-line binary wrapped in a process spawn. That is fine on a desktop and impossible on iOS, where fork/exec is not available at all.

The instinct is to port the C tools. But the system frameworks already do most of the work, in hardware, with no licence exposure — ImageIO encodes HEIC, AVIF, JPEG, PNG, GIF, TIFF, JPEG 2000 and PDF; AVFoundation probes and extracts frames; VideoToolbox encodes H.264 and HEVC with constant-quality control; Vision does OCR.

Lathe is the thin, well-tested layer over those frameworks — plus the few permissive libraries that fill the gaps they really do leave.

02 — Implemented

What works today

Media probing

Container headers via AVURLAsset — duration, per-track codec, coded and display dimensions, frame rate, bit rate, channels. No decoding, so a four-hour film costs what a four-second clip costs.

MediaProbe · MediaInfo

ffprobe-shaped output

The same facts in the shape ffprobe -of json emits, so a subprocess prober can be replaced in one reviewable change. Numeric-looking fields stay strings, because every parser written against ffprobe expects them to be.

MediaInfo.ffprobeJSON()

Loudness — and audibility

Two questions that are easy to mistake for one. A measurement, and a decision. The difference is the interesting part; see below.

LoudnessProbe

Still-image encoding

Format, quality, downscale-only resizing and metadata policy in one pass, with the capability checked before encoding so an unsupported format fails clearly instead of leaving an empty file.

ImageEncoder

Frame extraction

Thumbnails at a requested time and max edge; raw 8-bit grayscale frames for perceptual hashing, which never touch disk.

FrameExtractor

Capability probing

Asks the OS what it can encode by attempting a destination, never by reading a type list. Correct on OS versions nobody has tested — which matters, because some format identifiers carry no availability annotation at all.

EncodeSupport
03 — A detail worth the space

The audibility cliff

Mean volume over a whole file is the standard way to ask “does this have sound?” — and it is quietly wrong. Ten minutes containing two seconds of speech averages about −45 dBFS: indistinguishable, by that number, from a file with nothing in it at all.

That is not a corner case. It is an ordinary phone video with one spoken sentence in it.

// a measurement
let volume  = try await LoudnessProbe().meanVolumeDB(url: url)

// a decision — stops as soon as it has an answer
let audible = try await LoudnessProbe().hasAudibleAudio(url: url)

meanVolumeDB reports the same statistic the familiar command-line filter prints, so existing thresholds keep working. New logic should use hasAudibleAudio, which reads windowed peak and short-term RMS and returns the moment it knows. A loud file is decided in the first window; only a genuinely silent one is read to the end, because that is the only way to be sure.

04 — What it is for

Built to become Sami’s engine

Sami is a smart media optimizer for Apple Photos, folders and cloud drives — one universal app across iPhone, iPad and Mac. It reclaims storage by compressing exactly the photos, videos and PDFs you choose, with a side-by-side preview before anything is committed.

Lathe is the engine being built to replace the one underneath it. Every capability here — probing, loudness, frame extraction, still encoding, and the video path in progress — exists because a real shipping app needs it to work on a phone, offline, without spawning anything.

To be exact: Sami does not run on Lathe yet. Lathe is being built so that it can.

05 — Linking

One repo, separate products

Lathe ships several products, chosen individually. That split is not cosmetic — it is how an App Store target stays clear of code it should not contain.

ProductContentsApp Store
LatheThe media-processing modules, togetheralways safe
LatheCoreShared types, progress, errorssafe
LatheImageStill images, capability probesafe
LatheVideoProbing, frames, transcodingsafe
LatheDocPDF and archivessafe
LatheAudioLoudness and audibilitysafe
network ingestFetching from the network — not yet writtennever in the umbrella

The umbrella product is the media-processing modules and will never absorb a network-ingest module. Depending on Lathe therefore cannot pull one in by accident; linking one has to be a deliberate line in your own manifest.

07 — Not yet

Compression comparisons

Deliberately empty.

This will hold before/after comparisons with a draggable slider, real byte counts, real percentages saved and a quality score — each naming the tool it is measured against, because “40% smaller” means nothing without “…than what”.

Those figures will be generated by the test suite and regenerated on every release, not written by hand. Until the encoders are finished there is nothing to generate, and publishing numbers that nothing produced is exactly what that design exists to prevent.
